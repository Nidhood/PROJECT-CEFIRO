# Future alignment with CEFIRO FMU V3 (STM32H743)

This document is a design contract, NOT an instruction to enable the hardware ESC.

## Verified against the supplied `main.c`

The provided file is a sensor bring-up firmware for STM32H743ZIT6. It configures IMU via SPI5, magnetometer via SPI4, barometer via I2C2 and prints diagnostics over USART2, with a 10 Hz print loop. It contains **no DShot frame generation, GPIO/timer/DMA motor output, ESC telemetry readout, or ARM/DISARM motor command handling**. No unknown timer/pin assignment should be inferred from this source file.

## Proposed messages for ROS ↔ FC software architecture

Application-level command: `cefiro_msgs/msg/MotorRpm` with `float64[4] data` in mechanical RPM, which would need a **real speed controller plus RPM feedback** for precise tracking. In the current standalone simulation RPM requests are converted to feedforward throttle only.

Hardware-equivalent digital throttle: `cefiro_msgs/msg/MotorDshot` with `uint16[4] data`, where `0` stops and 48..2047 commands ordinary throttle. Fields 1..47 are reserved; this package refuses them by design. The 16-bit standard DShot word is constructed as:

```c
uint16_t dshot_packet(uint16_t throttle, uint8_t telemetry) {
    uint16_t payload = (uint16_t)((throttle << 1) | (telemetry & 1U));
    uint16_t crc = (uint16_t)((payload ^ (payload >> 4) ^ (payload >> 8)) & 0x0FU);
    return (uint16_t)((payload << 4) | crc);
}
```

This applies to standard **unidirectional** DShot; **bidirectional** protocols and their CRC processing differ. No physical waveform is generated by this ROS package.

## Future firmware and Gazebo checks

1. Determine the actual STM32H743 timer channels, GPIO alternate functions and DMA streams routed to each ESC signal input. Confirm that the ESC installed supports DShot300.
2. Implement nonblocking DMA generation of the 16-bit DShot frame, 3.333 µs per bit for DShot300, with waveform high-times according to the ESC firmware. Do not transmit the ROS message directly to a GPIO.
3. Verify arm/disarm startup and command-loss behavior **without propellers**. Provide an independent hardware emergency power cut.
4. If the ESC supports eRPM telemetry, convert electrical to mechanical RPM using the **actual motor pole count**, and validate against an independent tachometer. Do not assume the ESC regulates RPM.
5. Extend ROS telemetry with measured motor RPM and ESC faults; fit motor dynamics and coefficients before moving to an ESC-in-the-loop test.
6. Only in a subsequent phase, add Gazebo forces `thrust_n` and reaction moments `reaction_torque_nm` at actual rotor positions and axes while keeping the gimbal base fixed.

References: https://betaflight.com/docs/development/API/Dshot and https://docs.px4.io/main/en/peripherals/dshot
